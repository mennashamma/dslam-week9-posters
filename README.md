# Week 9 setup
Use a NEW Firebase project, not the Week 8 project. Create a web app and copy its firebaseConfig into config.js. Enable Email/Password authentication and create a Realtime Database. Publish database.rules.json in the Rules tab. Add your GitHub Pages hostname to Authentication > Settings > Authorized domains if needed.
Create accounts in Authentication > Users: one facilitator, one optional projection account, and one per student (use unique passwords and pseudonymous emails). Copy each UID into the Realtime Database Data tab under roster. Example data (replace UID placeholders):
{"roster":{"ADMIN_UID":{"role":"admin"},"DISPLAY_UID":{"role":"display"},"STUDENT_UID":{"role":"student","group":"A","label":"A1","active":true}},"state":{"phase":"waiting"}}
Repeat for all students; groups A–D. Do not put passwords or the roster in GitHub. Distribute credentials privately. Upload index.html, app.js and config.js to a new GitHub repository and enable Pages from main/root. All roles use the same URL. Open a separate browser profile for the display account. Mark absences before opening the first assessment. Open A, close, repeat for B–D. Enter facilitator scores and reveal. Export feedback privately. Exact ties are joint winners. No scores are published to students; only the winner. Test with dummy accounts before teaching, including forbidden self-scoring, duplicate submission and reading another student's review. Delete dummy reviews and facilitator scores and reset state using Firebase console before the real session. The code is not integration-tested. Do not use real student names or personal emails without appropriate institutional approval.
